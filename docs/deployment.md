# Deployment (Render)

`render.yaml` is a Render Blueprint that creates:

- **trading-db** – managed PostgreSQL;
- **trading-ai-api** – Python web service (`server/`), migrations in the pre-deploy step,
  `uvicorn app.main:app --host 0.0.0.0 --port $PORT`, health check `/health`, a 1 GB disk at
  `/var/data` for model artifacts;
- **trading-ai-dashboard** – static site built from `dashboard/`.

Free instances sleep when idle and are not suitable for 24/5 operation; the blueprint uses `starter`
(the disk also requires a paid instance). Check Render's current pricing before deploying.

## Steps

1. Push this repository to GitHub (never commit `.env`).
2. Render dashboard → **New › Blueprint** → select the repository → Render reads `render.yaml`.
3. Fill in the variables marked *sync: false* when prompted:
   - `EA_API_KEY_ID` – any id, e.g. `ea-cfi-01`
   - `XAUUSD_SYMBOL`, `OIL_SYMBOL`, `US30_SYMBOL` – exact MT5 names
   - `NEWS_PROVIDER` (`fmp`, `finnhub`, `tradingeconomics`) and `NEWS_API_KEY`
     (without a working provider the system stays in SAFE MODE and never trades — by design)
   - `CORS_ORIGINS` – the dashboard URL, e.g. `https://trading-ai-dashboard.onrender.com`
   - dashboard `VITE_API_URL` – the API URL, e.g. `https://trading-ai-api.onrender.com`
   `JWT_SECRET`, `EA_HMAC_SECRET` and `API_KEY` are generated by Render. Open the API service's
   **Environment** tab to read `API_KEY` (dashboard login) and `EA_HMAC_SECRET` (EA input).
4. **Apply**. When the API is live: `https://<api>/health` → `{"status":"ok","database":true,"trading_mode":"PAPER"}`.
5. Redeploy the dashboard after setting `VITE_API_URL` (it is baked in at build time).
6. In MT5 add the API URL to the WebRequest list and set `InpBackendUrl` (see mt5-setup.md).
7. Run the smoke test from the Mac:
   ```bash
   BACKEND_URL=https://<api> EA_API_KEY_ID=... EA_HMAC_SECRET=... API_KEY=... python scripts/smoke_test.py
   ```

## Environment variables

All settings are listed with comments in `.env.example`. Safety-relevant ones are pinned in
`render.yaml`: `TRADING_MODE=PAPER`, `ENABLE_LIVE_TRADING=false`, risk limits. Secrets never go in Git.
Render's `postgres://` URL is converted automatically to the psycopg driver URL.

## Models on Render

Model artifacts are files. `MODELS_DIR=/var/data/models` on the persistent disk. Train on the Mac with
`DATABASE_URL` pointing to the Render database (External Database URL) and copy the `.joblib`/`.json`
into the disk (Render Shell, `scp` via Render SSH), or train inside a Render Shell. Without a model the
backend runs RULE_BASED in PAPER/DEMO (if allowed) and refuses LIVE trades.

## Operations

- Logs: Render → service → Logs (structured JSON, one line per request/decision).
- Metrics: `GET /v1/metrics` (API latency, signal latency, rejections, auth failures, error rate).
- Alerts: set `TELEGRAM_BOT_TOKEN`/`TELEGRAM_CHAT_ID`, `ALERT_WEBHOOK_URL` or SMTP variables.
- Rate limiting is per process; with multiple instances set `REDIS_URL` (Render Key Value).
- Deploying a new version restarts the API: the EA sees the backend offline for a few seconds and
  simply makes no new trades meanwhile; open positions stay managed by the EA.

## Docker (local or any host)

```bash
docker build -t trading-ai-api .
docker run --env-file .env -e DATABASE_URL=postgresql://... -p 8000:8000 trading-ai-api
```
The container runs `alembic upgrade head` and then uvicorn on `$PORT` (default 8000) as a non-root user.
